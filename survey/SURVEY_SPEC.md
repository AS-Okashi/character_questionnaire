# ASTERIA Survey v1 — fixed protocol

## Flow

1. 研究説明・同意
2. 参加者属性
3. PART 1説明
4. 基準キャラクター10人（ランダム順）
5. PART 2説明
6. 衣装変化10人（PART 1と独立ランダム順）
7. 任意自由記述
8. 確認・GAS送信
9. 終了

PART 1最後のキャラクターとPART 2最初のキャラクターが同一になった場合は、PART 2の先頭2件を入れ替えます。

## Participant attributes

- D1 年齢（数値）
- D2 性別：男性 / 女性 / その他 / 回答しない
- D3 キャラクターコンテンツへの関心（1–7）
- D4 キャラクター衣装・外見デザインへの関心（1–7）
- D5 ファッションへの関心（1–7）
- D6 「ギャップ萌え」の語への馴染み（1–4）

## Impression items — PART 1 / PART 2 common

すべて1–7件法。

- I1 このキャラクターは「かわいい」と感じる
- I2 このキャラクターは「かっこいい」と感じる
- I3 このキャラクターは「落ち着いている」と感じる
- I4 このキャラクターは「活発である」と感じる
- I5 このキャラクターは「大人っぽい」と感じる
- I6 このキャラクターは「親しみやすい」と感じる

## Outfit-change appraisal items

- G1 衣装変更後の姿は、最初に抱いたこのキャラクターの印象と異なると感じた
- G2 この衣装変化を意外だと感じた
- G3 衣装が変わっても、同じキャラクターらしさが保たれていると感じた
- G4 この衣装は、このキャラクターに似合っていると感じた
- G5 衣装変更によって、このキャラクターの魅力が増したと感じた
- G6 衣装変更後の姿に違和感を感じた

## Gap-Moe response items

- GM1 この衣装変化にギャップ萌えを感じた
- GM2 元の印象との違いそのものに魅力を感じた
- GM3 このキャラクターの意外な一面に惹かれた

GM1をPrimary Outcomeとして扱い、GM2・GM3は補助的な反応指標として保持する想定。

## Variant assignment

各キャラクターに3枚の変換画像 `a/b/c` を用意する。参加者はUUIDから0/1/2の3群へ割り当てる。キャラクターindex `i` とgroup `g` に対して、提示variantは `(i + g) mod 3` とする。

これにより各参加者は各キャラクター1変換だけを評価し、3群全体では各キャラクターの3variantを均等に評価できる。

**a/b/cは刺激作成時の内部識別子であり、参加者には表示しない。生成意図を正解ラベルとして分析に使用しない。**

## Data transport

GitHub Pages上の静的フォームからGASへhidden form POSTを行う。`payload` に全回答JSON、`nonce` に送信確認用IDを格納する。GASは保存後、iframe内から `window.parent.postMessage` を送信し、ブラウザはnonce一致かつ `ok=true` を確認してから完了画面へ遷移する。
